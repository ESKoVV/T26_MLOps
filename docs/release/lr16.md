## Статус: draft — и почему

`release_status` = `draft`: нет независимого одобрения (`approved_by` пуст, автор — @ESKoVV). Manifest станет
`ready_with_exception`, когда участник команды (не автор) проверит evidence и впишет себя в `approvals.approved_by`:

```bash
python -m mlops_flight_delay.release build --spec release/release_spec.json --policy release/release_policy.json \
  --output reports/releases/lr16-manifest.json --require-ready
python -m mlops_flight_delay.release verify --manifest reports/releases/lr16-manifest.json --policy release/release_policy.json
```

## Найденные в ЛР16 дефекты

1. Spec мог заявить gate `pass`, хотя JSON evidence говорит `status: review` (именно так было бы с ЛР14). Теперь build
   отказывает и требует `accepted_with_investigation` с исключением.
2. Одобрение `ESKoVV` релиза, подготовленного `eskovv`, считалось независимым. Сравнение логинов теперь без учёта регистра и пробелов.

## Сценарий демонстрации (≈ 5 минут)

1. `git show --stat 21e2d28` — source commit; CI run из spec — зелёные `quality` и `container`.
2. `dvc pull && sha256sum data/bts/atl_2026.csv` — совпадает с `data.sha256` в manifest.
3. `python -m mlops_flight_delay.release verify …` — все hashes evidence совпали.
4. Отказ: копия spec с `image.ref = …:latest` → `Плавающий tag latest запрещён`; копия с `responsible_ai: pass` →
   `evidence сообщает status=review`.
5. `MlflowClient().get_model_version_by_alias('team-3-flight-delay-classifier', 'champion').version` → `1`.
6. API: `uvicorn …` → `/readyz` 200 → `scripts/api_contract_smoke.py` 4/4.
7. Rollback: `registry rollback --target-version 2` → smoke → возврат на v1 (команды в `docs/registry/lr10.md`).

## Ограничения итогового выпуска

- ЛР6 (контейнер локально) и ЛР11 (Prometheus/Grafana) ждут Docker на машине тимлида; образ собирается и проверяется только в CI.

- Модель слабая (test ROC AUC 0.631, два признака) — проект демонстрирует процесс, а не прогноз.
