# Карточка модели team-3-flight-delay-classifier

Версия карточки: 2.0.0 (2026-10-28). Статус: учебная модель курса MLOps; не разрешена для решений в реальной эксплуатации.

## Краткое описание

Бинарный классификатор оценивает вероятность того, что рейс прибудет с задержкой не менее 15 минут.
Прогноз строится за 60 минут до планового вылета. Выпущенная версия: MLflow Registry
`team-3-flight-delay-classifier` v1 (alias `champion`), run `674de9fa758d460b8df38d066c4ab1b2`, source commit `5a25637d`.

## Назначение

Учебная демонстрация полного MLOps-цикла на реальных публичных данных BTS: диспетчер видит рейсы с повышенным
риском задержки и решает, какие проверить. Модель только подсказывает порядок внимания, решение остаётся за человеком.

## Недопустимое использование

Запрещены решения о пассажирах, сотрудниках, перевозчиках, компенсациях, безопасности полёта и реальной работе аэропорта.
Нельзя применять модель к другим аэропортам, сезонам и годам без новой оценки: обучение — только ATL, январь–февраль 2026.

## Модель и данные

- Алгоритм: `RandomForestClassifier` scikit-learn, `n_estimators=120`, `max_depth=8`, `random_state=42` (выбор по validation в ЛР4).
- Признаки: `DepHour` (час планового вылета), `IsWeekend`. Цель: `ArrDelay >= 15`. `ArrDelay` в признаки не входит.
- Данные: фрагмент BTS On-Time Performance, вылеты из ATL без отменённых и перенаправленных рейсов, 45 954 рейса
  (DVC md5 `bb0fdbb6…`, SHA-256 `78721daf…`), контракт `data/contract_bts.json`, карточка — `docs/data-card.md`.
- Разбиение по календарным дням: train 01-01 — 02-05, validation 02-06 — 02-16, test 02-17 — 02-28.

## Оценка качества

| Метрика | Validation | Test |
|---|---:|---:|
| ROC AUC | 0.576 | 0.631 |
| F1 при пороге 0.19 | 0.274 | 0.428 |
| Precision / recall при 0.19 | — | 0.348 / 0.554 |
| Доля рейсов, помеченных «задержка» | — | 0.415 |
| F1 при пороге 0.5 | 0.000 | 0.000 |

Порог 0.19 выбран по максимуму F1 **на validation** (`scripts/build_governance_eval.py`, `reports/governance/lr14-threshold.json`);
test открыт один раз. При пороге 0.5 модель не помечает ни одного рейса — доля задержек всего 0.15–0.26.
Test ROC AUC выше validation не потому, что модель стала лучше: в test выше доля задержек и сильнее связь с часом вылета.

## Групповые метрики

Сегмент `IsWeekend` на test (политика `governance/responsible_ai_policy_bts.json`, минимум 200 строк на группу):

| Группа | Рейсов | Доля задержек | ROC AUC | F1 |
|---|---:|---:|---:|---:|
| будни (0) | 7 427 | 0.228 | 0.581 | 0.327 |
| выходные (1) | 2 224 | 0.372 | 0.624 | 0.583 |

Разрыв F1 — 0.256 при лимите 0.25: аудит выдаёт `review`. Основная причина — разная доля задержек в группах (F1 растёт с базовой
частотой положительного класса), ROC AUC отличается меньше (0.04). `IsWeekend` — операционный сегмент, а не защищённая группа;
результат не доказывает и не опровергает справедливость модели. Решение по разрыву — в `docs/governance/lr14.md`.

## Ограничения и риски

- Всего два слабых признака: нет перевозчика, маршрута, погоды и накопленной задержки борта.
- Один аэропорт и два зимних месяца; другой сезон даст другой профиль задержек.
- Время в BTS местное, без часового пояса; момент прогноза восстановлен приближённо.
- Неравная цена ошибок: пропущенная задержка дороже лишней проверки, отсюда низкий порог и высокий recall.

## Мониторинг и реакция

Контролируются latency и ошибки API, PSI признаков, coverage отложенных меток и ROC AUC по зрелым меткам
(`monitoring/drift_policy_bts.json`, отчёты ЛР12). Drift без падения качества — расследование; падение ROC AUC ниже 0.58 —
incident review. Автоматического переобучения нет. Откат — alias `champion` на предыдущую версию (отработан в ЛР10).

## Безопасность и конфиденциальность

Персональных данных нет: строка — рейс. Секреты в Git, отчётах и логах не хранятся; запрос к API содержит только два признака,
входные признаки в логи не пишутся, `X-Request-ID` фильтруется. Повреждённый файл модели останавливает старт сервиса.
Угрозы и контроли — `docs/security/threat-model.md`.
