# ADR 0001 Границы учебного проекта

Статус: принято командой team-3
Дата: 2026-10-28

## Контекст

Команде нужен один репозиторий, который проходит все 16 ЛР курса MLOps. Пользователь результата —
диспетчер авиакомпании: за 60 минут до планового отправления ему нужна вероятность того, что
рейс прибудет с задержкой не менее 15 минут, чтобы заранее перераспределить экипажи и гейты.

## Решение

- Основа — стартовый проект курса `flight-delay`. Отдельную тему команда не вводит: так каждая
  следующая ЛР расширяет уже проверенный код, а не начинается заново.
- Входные данные: обезличенный учебный набор `data/flights_sample.csv` (контракт 2.0.0). Полный
  набор BTS в Git не кладётся.
- Признаки — только то, что известно до прогноза: `DepHour`, `IsWeekend`. `ArrDelay` даёт цель
  `ArrDelay >= 15` и в признаки не входит.
- Разбиение только по времени: train/validation/test 60/20/20 по `FlightDate`.
- Метрика качества модели — ROC AUC на validation; test открывается один раз для итогового отчёта.
- Эксплуатационный показатель — p95 latency `/predict` не более 300 мс и доля 5xx ниже 1 %.
- Компоненты итогового проекта: валидация данных, DVC, MLflow Tracking и Registry, pytest,
  FastAPI, Docker и Compose, GitHub Actions, Prefect, Prometheus и Grafana, отчёты drift и
  release manifest.

## Риски

1. Данные: в признаки может попасть величина, которая известна только после прилёта (утечка).
   Обнаруживается контрактом (`role: target_source`) и тестом хронологического разбиения.
2. Воспроизводимость: зависимости без верхних границ или другая версия Python дают иной результат.
   Обнаруживается CI на Python 3.12 из `.python-version` и установкой по README в чистом каталоге.
3. Эксплуатация: сервис стартует без модели и отвечает ошибкой на `/predict`. Обнаруживается
   `/readyz`, который успешен только после загрузки модели, и smoke-тестом контейнера.

## Последствия

Проще: интерфейсы запуска одинаковы во всех ЛР, а CI проверяет весь путь от данных до manifest.
Сложнее: учебный набор маленький (24 строки), поэтому метрики шумные и не годятся для выводов
о реальном качестве — это прямо указывается в отчётах.

## Отложено

- Политика хранения данных и DVC remote — ЛР2–ЛР3.
- Выбор гиперпараметров и сравнение run — ЛР4.
- Порог SLO под реальную нагрузку — ЛР11 и ЛР15, после первых измерений.
