# Threat model учебного ML-сервиса

## Активы и границы доверия

Активы: код, учебные данные, модель, registry metadata, CI credentials, контейнер, отчёты и журнал решений. Границы: GitHub/runner, artifact storage, registry, контейнерный runtime, HTTP API и локальные рабочие станции.

## Основные угрозы и контроли

| Угроза | Возможное последствие | Контроль | Остаточный риск |
|---|---|---|---|
| секрет в commit или логе | захват внешнего ресурса | secret scanning, push protection, ротация, маскирование | ложные отрицания сканера |
| подмена зависимости или action | выполнение чужого кода | review lock-файлов, pin версий, SBOM, минимальные permissions | компрометация доверенного источника |
| изменение данных/модели без trace | невоспроизводимый выпуск | commit SHA, hashes, registry version, CI evidence | ошибка владельца метаданных |
| невалидный HTTP-ввод | отказ или неверный прогноз | Pydantic schema, size/range limits, единый error contract | неизвестный сценарий нагрузки |
| утечка данных через observability | раскрытие входов | allowlist полей, запрет raw features и секретов | ошибочный новый лог |
| poisoning или leakage | ложное качество | contracts, chronological split, PIT-тесты, review происхождения | неполное знание источника |

## Реакция

При подозрении на секрет немедленно отозвать/ротировать его, затем удалить причину и проверить историю. При нарушении происхождения данных или модели остановить release, сохранить evidence, назначить владельца и выполнить контролируемый rollback.
