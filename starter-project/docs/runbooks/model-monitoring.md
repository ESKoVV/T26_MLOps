# Runbook: drift и отложенное качество

## Сигналы

- `drift.status=warning|alert` — изменилось распределение признаков относительно reference-окна;
- `delayed_quality.status=insufficient_evidence` — метки ещё не созрели или coverage ниже порога;
- `delayed_quality.status=quality_breach` — ROC AUC или F1 ниже policy;
- `decision.action` — рекомендуемое действие, но не автоматический выпуск новой модели.

## Первые проверки

1. Сверить `policy_version`, временные границы, model version и release manifest.
2. Проверить контракт данных, пропуски, диапазоны и появление новых категорий.
3. Убедиться, что в знаменатель coverage входят только прогнозы старше ожидаемой задержки метки.
4. Проверить уникальность `request_id` и корректность времени в UTC.
5. Сравнить сигнал по сегментам и проверить объём окна.

## Действия

- `hold`: дождаться меток или исправить join; переобучение запрещено.
- `investigate`: исследовать источник drift, не считать его доказательством падения качества.
- `incident_review`: проверить pipeline меток, модель и бизнес-процесс.
- `retraining_review`: открыть issue, подготовить candidate и сравнить его с champion через gates ЛР10.

## Завершение

Сохранить исходные окна, JSON-отчёт, ссылку на issue/PR, принятое решение и владельца.
Новая модель получает alias `champion` только после review и проверки release manifest.
